# ML-эксперимент

Хроника датасета, выбор модели, смена задачи и сохранённые результаты.

## Датасет

Все фотографии я генерировал в `Nano Banana Pro`. Промпты немного менялись, но главное условие сохранялось: в кадре должен быть талевый канат с нужным типом дефекта. 

Всем желающим я выгрузил паки в [`../prompts/`](../prompts/) в их оригинальном виде

### Разметка

Размечалось всё вручную через Roboflow

Есть три класса дефектов:
| Класс | Смысл |
|:---|:---|
| `broken_wire` | обрыв наружных проволок |
| `corrosion` | коррозионное повреждение |
| `kink_or_bend` | залом / перегиб каната |

Изображения `normal` я решил использовать как отрицательные примеры: если на изображении нет дефекта, label-файл остаётся пустым, а модель учится не создавать лишний bbox.

Реальным допущением было с моей стороны наличие одного дефекта на каждую фотографию, чтобы было легче учиться и обрабатывать, в реальных условиях возможны и два, и три (одинаковых или различных) дефекта на разных кусках каната, повреждения в bbox включались целиком

### Эволюция датасета

Первая версия включала 100 изображений, по 25 на каждую группу


Затем расширение было следующим: +24 изображения `broken_wire`, +25 `kink_or_bend` и +13 `normal`. 
`corrosion` с самого начала себя показала хорошо, расширять смысла не было


| Группа | Train | Val | Test | Всего |
|:---|---:|---:|---:|---:|
| `broken_wire` | 34 | 10 | 5 | 49 |
| `corrosion` | 18 | 5 | 2 | 25 |
| `kink_or_bend` | 35 | 10 | 5 | 50 |
| `normal` | 26 | 8 | 4 | 38 |
| **Всего** | **113** | **33** | **16** | **162** |

## Выбор модели

В качестве базовой модели я использовал YOLOv8s с предобученными весами.

Мне нужна была именно object detection модель, потому что задача заключалась не только в определении наличия дефекта, но и в локализации повреждённого участка через bounding box.

Версию `s` я выбрал как достаточно компактную модель для прототипа и потенциального дальнейшего запуска на edge-устройстве. Полноценного benchmark между YOLOv8n/s/m и другими архитектурами в этой работе я не проводил.

## Multiclass

Первый эксперимент проводился как трехклассовый object detection:

- `broken_wire`
- `corrosion`
- `kink_or_bend`

Модель должна была одновременно локализовать дефект и определить его тип.

По результатам validation качество оказалось заметно различным между классами. Лучше всего модель работала с `corrosion`, а самым проблемным оказался `broken_wire`.

| Класс | Precision | Recall | mAP@0.5 |
|:---|---:|---:|---:|
| `broken_wire` | 0.526 | 0.500 | 0.489 |
| `corrosion` | 0.790 | 0.760 | 0.866 |
| `kink_or_bend` | 0.498 | 0.900 | 0.793 |
| **Среднее** | **0.605** | **0.721** | **0.716** |

После этого датасет расширялся неравномерно: дополнительные изображения в первую очередь добавлялись для слабых групп.

При дальнейшем анализе я решил, что для первой версии прототипа важнее надёжно определить наличие подозрительного участка, чем обязательно правильно определить конкретный тип дефекта. Поэтому следующий эксперимент проводился уже с одним классом `defect`.

## Смена постановки задачи

После повторного обучения расширенной модели и обдумывания задачи прототипа было принято решение о переходе к бинарной классификации

Все три исходных класса объединяются в `defect`, а `normal` остаётся отрицательным примером с пустой разметкой

Причина перехода была практической. Для демонстрационной модели этого было достаточно, сама постановка позволила показать на практике систему принятия решений и ведение журнала дефектов

## Конфигурация обучения

Финальная binary-модель обучалась через transfer learning на предобученных весах `yolov8s.pt`.

| Параметр | Значение |
|:---|---:|
| Model | YOLOv8s |
| Image size | 640 |
| Epochs | 150 |
| Batch | 8 |
| Patience | 50 |
| Seed | 42 |
| Pretrained | true |

Из аугментаций использовались небольшие повороты, сдвиги, масштабирование, горизонтальное отражение, изменение HSV и ограниченный mosaic.

```text
degrees=3.0
translate=0.04
scale=0.20
fliplr=0.5
mosaic=0.25
close_mosaic=20
hsv_h=0.01
hsv_s=0.25
hsv_v=0.20
```
## Binary — сохранённые результаты

После объединения исходных типов дефектов модель обучалась как object detection с одним классом `defect`. Изображения `normal` оставались отрицательными примерами с пустыми label-файлами.

### Validation

| Метрика | Значение |
|:---|---:|
| Precision | 0.847 |
| Recall | 0.560 |
| mAP@0.5 | 0.738 |
| mAP@0.5:0.95 | 0.263 |

### Image-level test

Для итоговой проверки результат детекции дополнительно сводился к ответу `defect / no defect`. Если максимальный `camera_conf >= 0.35`, изображение считалось содержащим дефект.

| Метрика | Значение |
|:---|---:|
| Найдено дефектных изображений | 11 из 12 |
| Precision | 91.7% |
| Recall | 91.7% |
| Accuracy | 87.5% |

Test split состоял из 16 изображений: 12 дефектных и 4 `normal`. Поэтому эти результаты стоит воспринимать как проверку прототипа на небольшой синтетической выборке, а не как оценку промышленной точности.

Image-level метрики здесь описывают итоговый ответ `defect / no defect`, а не качество локализации bounding box.

## Ограничения интерпретации

- все изображения синтетические
- выборка небольшая
- изображения создавались одним генеративным процессом
- для положительных примеров размечалась одна доминирующая зона дефекта
- split формировался автоматически и менялся при расширении набора
- test состоит из 16 изображений
- порог `0.35` не является промышленно откалиброванным
- сравнение YOLOv8n/s/m и других архитектур не проводилось
- переносимость результатов на реальные буровые фотографии не проверялась.
